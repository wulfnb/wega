# V8 engine plan: from QuickJS shim to a real-site engine

Status: **approved plan, not yet implemented.** Written on 25 October 2026 after a
successful spike. This document is the handover for whoever implements it, person or
AI agent. Read it top to bottom before changing code. The background design is in
[engine-strategy.md](engine-strategy.md), and the decision is recorded in
[architecture-decisions.md](architecture-decisions.md).

## 1. Summary

The Wega engine (`engines/wega`, a Blitz-based worker with one process per tab)
replaces **QuickJS-ng** with **V8**, embedded through Deno's MIT-licensed `deno_core`
crate. Deno's tested Web API crates supply `fetch`, events, timers, streams, URL,
storage, WebSocket and crypto. Wega writes the DOM bindings onto Blitz's single
Rust DOM.

Order of work: **P0** safety net (needed whatever the VM) → **P1** V8 inside the
engine → **P2** Deno Web APIs → **P3** DOM bindings → **P4** speed and RAM → **P5** CSS
completeness → **P6** rollout. QuickJS stays available behind a cargo feature until V8
passes every gate up to P3.

## 2. Why

**Today's bug.** Real pages fail with
`JavaScript failed or exceeded its limit: TypeError: not a function`. Two causes:

1. `engines/wega/src/dom.js` is a 52-line hand-written DOM shim. Element-level
   `querySelector`, `insertBefore`, `removeChild`, `cloneNode`, `closest`,
   `innerHTML`, `style`, `dataset`, `dispatchEvent`, `requestAnimationFrame`,
   `matchMedia`, `fetch` and most other APIs are missing. Calling one is `undefined()`,
   and QuickJS-ng's message does not say which name was missing.
2. `View::run` in `engines/wega/src/view.rs` sets `self.script = None` on **any**
   exception, as does `poll()` when a timer throws. After one missing API, every later
   script, timer and listener on the page is dead. Browsers report the error and carry
   on.

`ScriptHost::dispatch` and `evaluate_json` in `engines/wega/src/script.rs` also drop
the exception text (`e.to_string()` gives "Exception generated by QuickJS").

**Goals.** Run jQuery, React, Vue and Angular sites with modern CSS and SVG; be fast;
keep RAM well below Servo's ~500 MB per busy page (see engine-strategy.md); reuse
permissively licensed implementations instead of writing everything.

**Why V8.** QuickJS-ng and Boa are interpreters: React/Angular-scale apps run
10–50× slower than with a JIT. V8 has a JIT, close to 100% language conformance,
WebAssembly, heap caps, termination and startup snapshots. Through `deno_core` it also
brings Deno's WPT-tested Web APIs.

## 3. Spike evidence (25 October 2026)

Spike: `engines/v8-spike` (standalone workspace, not part of the product). It parses a
page with Blitz 0.3.0-beta.4, runs the same script through either VM via a native
`__host(op, a, b)` bridge, mutates Blitz's DOM, paints with Vello CPU and checks
pixels. Each engine runs in its own process so RSS is comparable. macOS arm64,
release build.

| Engine | `fib(30)` | 20,000 DOM `textContent` writes | Peak RSS after JS | Peak RSS after paint |
| --- | --- | --- | --- | --- |
| V8 (JIT) | 17–22 ms | 16–28 ms | 43–44 MB | ~50 MB |
| V8 `--lite-mode` | 157–170 ms | 28–30 ms | ~36.5 MB | |
| V8 `--jitless` | 183–196 ms | 44–78 ms | ~37 MB | |
| QuickJS-ng | 146–298 ms | 18–38 ms | ~24.5 MB | ~32 MB |

- **It links.** V8 (`v8` 150.4.0 via `deno_core` 0.413.0) and Blitz resolve and link in
  one Cargo graph. The ICU conflict that split Servo from the engine does not occur:
  Blitz uses pure-Rust icu4x 2.4, while V8 bundles its own C++ ICU.
- JS compute is **8–15× faster** in V8. The DOM bridge costs the same in both VMs, so
  bridge design (fast ops, batching) matters more than the VM there.
- V8 costs **~12–20 MB more per tab** at baseline: small against Servo, and lite mode
  narrows it. These are tiny-page numbers, not real-site numbers.
- The release binary with **both** VMs is 80 MB. A first clean build takes about 5 minutes.
- The full future graph (Blitz + deno_core + `deno_web/webidl/fetch/webstorage/
  websocket/crypto`) also resolves together (657 crates).

Gotchas found:

- deno_core needs a **tokio runtime entered before `JsRuntime::new`**, otherwise V8
  aborts with "V8 posted a delayed task … outside of a tokio runtime context".
- `JsRuntime::handle_scope()` no longer exists in 0.413. The spike passes results
  back through an op instead.
- With a mirror configured, the v8 build script also copies
  `src_binding_<features>_<profile>_<target>.rs` from the mirror.

Rerun: `cd engines/v8-spike && cargo build --release && ./target/release/v8-spike v8`
(or `quickjs`; `V8_FLAGS="--lite-mode"` for V8 modes).

## 4. Deno, Cloudflare and our copies

Cloudflare announced the acquisition of Deno on 9 October 2026. The code **stays
MIT-licensed open source**, but Deno runtime development ends about 12 months after the
announcement, with monthly fixes until then. Our risks:

1. No upstream V8 security updates for `rusty_v8`/`deno_core` after that.
2. The `v8` crate downloads prebuilt static libraries from `denoland/rusty_v8` GitHub
   releases at build time, and those could disappear.

Mitigation, already in place:

- **In-repo:** `engines/vendor/deno/` holds the unmodified sources of `deno_core`
  0.413.0, `deno_ops` 0.289.0, `serde_v8` 0.322.0 and `deno_v8` 0.5.0, with Deno's MIT
  license. The spike uses them through `[patch.crates-io]`. P1 moves that patch into
  `engines/Cargo.toml`.
- **Local mirror** (outside git, ~2 GB): `/Users/noufalbabu/dev/personal/wega-mirrors/`.
  It contains full git mirrors of `denoland/deno`, `denoland/rusty_v8` and Deno's helper
  crates; prebuilt V8 libraries and bindings for the 5 release targets with SHA-256 sums;
  and a `cargo vendor` of the whole graph, including the full V8 C++ source. See its README.
- **Offline build verified:** the spike built from scratch with no network using
  `RUSTY_V8_MIRROR=<mirror>/rusty_v8-prebuilt` and `cargo --offline` with the vendored
  sources, and still rendered "V8 works".

Automated by `.github/workflows/v8-engine.yml`, which is separate from CI/CD:

- **CI** (pull requests touching `engines/v8-spike`, `engines/vendor` or this document):
  the vendored Deno sources must be byte-identical to crates.io, and the spike must pass
  fmt and clippy, build and run with V8 and QuickJS on Linux, macOS and Windows. The
  `V8 Engine Gate` job summarizes the results.
- **CD** (push to `main`, weekly on Mondays, manual): every prebuilt V8 file pinned in
  `engines/vendor/deno/V8-PREBUILT-SHA256SUMS` must still download from
  `denoland/rusty_v8` with a matching checksum. The first successful run publishes them
  as this repository's `deno-v8-mirror-150.4.0` pre-release, an offsite copy. A failing
  weekly run is the early warning that upstream removed them.

P1 extends this workflow to the real engine (`engines/Cargo.toml`) and bumps
`V8_VERSION`, the checksum file and the mirror tag together whenever V8 is upgraded.

Still to do (owner): copy the local mirror to a second disk (the workflow above
already keeps the prebuilt V8 files offsite). After upstream stops: rebuild V8 with security fixes
from our `rusty_v8` mirror (`V8_FROM_SOURCE=1`), or move to a community fork if one
appears. Review this at the 12-month mark (October 2027).

Note: `deno_console` and `deno_url` are no longer published separately. Their APIs live in
`deno_web` in the 0.413 generation.

## 5. Target architecture (inside one tab worker)

```text
browser UI ──pipe (engine_protocol)──▶ wega-engine worker (one per tab)
                                        ├─ blitz-dom BaseDocument   ← the only DOM (style, layout, paint)
                                        ├─ DOM bindings (JS classes) ──fast ops──▶ blitz-dom
                                        ├─ ScriptHost trait
                                        │    ├─ v8.rs: deno_core JsRuntime (+ deno_web, fetch, …)
                                        │    └─ quickjs.rs: existing rquickjs code (feature, temporary)
                                        ├─ event loop: tokio current-thread, driven by main.rs
                                        ├─ network: NetworkPolicy (later a shared broker, P4)
                                        └─ raster: Vello CPU → Skia (P5), own thread (P4)
```

Rules:

- **One DOM.** JS objects hold node ids. Rust owns nodes, and wrappers are cached per
  node so `===` holds. No JS-side DOM copy (no happy-dom/linkedom *as the DOM*).
- The DOM main thread is single-threaded (web semantics). Parallelism goes around it.
- Every limit that exists today stays (heap, script time, nodes, text bytes, resource
  sizes, pixels).

## 6. Phases

Each phase ends with its **gate**. Do not start the next phase until the gate passes
from a clean target.

### P0: safety net (VM-agnostic, do first)

Tasks:

1. **Error isolation** (`engines/wega/src/view.rs`, `src/script.rs`): classify errors as
   *fatal* (interrupt or deadline, out of memory, stack overflow, which tear the VM down)
   or *script* (an ordinary exception, which becomes a notice while the page keeps
   running). The next `<script>` still runs. In `dom.js`, each listener in the dispatch
   loop and each timer callback gets its own try/catch and reports through a host `error`
   op; fire `window.onerror` and the `error` event.
2. **Diagnostics:** notices contain `name: message`, the script source (URL or
   `inline #n`) and the top stack frames. Fix `dispatch`/`evaluate_json`/`tick` so
   they keep exception text. Add a **missing-API tracker**: wrappers are Proxies whose
   `get` trap records names resolving to `undefined`. On a `TypeError`, the notice lists
   them (`missing: Element.closest`). P6 reuses this to trigger the Servo fallback.
3. **Tests**, written against the `View` API only so they run unchanged on V8:
   - `engines/wega/tests/errors.rs`: a missing function names the API and source;
     the next script runs; earlier timers and listeners survive; a throwing listener does
     not block the others; a throwing timer does not stop the others; interrupt and OOM
     remain fatal (the existing tests in `tests/pages.rs` stay green).
   - `engines/wega/tests/compat.rs` with `engines/wega/tests/fixtures/`: offline
     framework pages using vendored minified builds of jQuery, React + ReactDOM, Vue,
     Preact, an Angular hello-world bundle, and an inline-SVG page. Each fixture clicks or
     dispatches and asserts DOM text or pixels. Mark the fixtures that fail on QuickJS as
     `#[ignore = "needs P3"]`. They are the acceptance list for later phases.
   - Prove every regression test by mutation: revert each rule and check that exactly its
     test fails.

Gate: `cargo test` for `engines/` passes; every P0 rule has a mutation-proven test;
clippy and fmt are clean.
Out of scope: adding missing DOM APIs to `dom.js`. The shim is replaced in P1/P3.

### P1: V8 inside the engine

Tasks:

1. Move the `[patch.crates-io]` for `engines/vendor/deno/*` into `engines/Cargo.toml`,
   add `deno_core = "=0.413.0"`, and update `engines/Cargo.lock`. Never add Servo crates
   to this workspace.
2. Add a `ScriptHost` trait in `engines/wega/src/script.rs`: `run`, `dispatch`,
   `evaluate_json`, `tick`, `next_timer`, `heap_bytes`, `freeze`. Move today's code to
   `quickjs.rs` and add `v8.rs`. Cargo features: `v8` (default) and `quickjs`.
3. The V8 host: a `JsRuntime` with the heap limit from `Limits::js_heap_bytes`
   (`CreateParams::heap_limits`), a near-heap-limit callback that terminates the isolate
   and reports OOM, and `terminate_execution` from a watchdog for the `script_time` budget.
   Ops replace `__wega_host` with **typed `#[op2(fast)]` ops** (no JSON per call). Port
   `dom.js` features to `src/dom/*.js`, loaded as an extension ESM/JS.
4. Event loop: create a tokio current-thread runtime in `engines/wega/src/main.rs`
   and enter it before the runtime. The loop currently blocks on `recv_timeout`; each
   iteration also polls `JsRuntime::poll_event_loop` without blocking, and its wake-up
   joins the existing `Work::Wake` path.
5. Flags: a per-view `lite` option (`--lite-mode`), off by default for now.
6. Build and packaging: `scripts/build-wega-engine.py`, the release packaging scripts,
   Docker and CI (`.github/workflows/ci.yml` "Build and test the independent Wega
   engine") work with V8. CI sets `RUSTY_V8_MIRROR` only if GitHub downloads fail. Update
   the engine third-party notices (`about.toml`/`about.hbs` and `NOTICE`) for V8 (BSD-3) and
   the Deno crates (MIT).

Gate: all of `tests/pages.rs` and P0 pass with `--features v8` **and** `--features
quickjs`; `python3 scripts/native-tests.py --suite engine` passes; worker binary size
and idle RSS are recorded in this document.

### P2: Deno Web APIs

Add `deno_webidl` 0.260, `deno_web` 0.291 (Event/EventTarget, timers,
`AbortController`, Blob/File, streams, TextEncoder/Decoder, URL, console,
`structuredClone`, `performance`), `deno_fetch` 0.284, `deno_webstorage` 0.255,
`deno_websocket` 0.265 and `deno_crypto` 0.274. Implement their permission traits with
`NetworkPolicy` (`engines/wega/src/network.rs`); file access is never allowed for web
content. `localStorage` goes in a per-profile directory passed in `Command::Init`, with
a size cap. Write XHR as a thin layer over the fetch op (jQuery `$.ajax` and older sites
need it).

Gate: fixtures for `fetch`, XHR and `$.ajax` against a local test HTTP server in the
test; policy tests prove blocked hosts and offline mode for fetch and WebSocket.

### P3: DOM bindings

Implement in JS classes over fast ops into blitz-dom, generated from WHATWG IDL where
practical (`weedle2`, MIT, to parse):
Node, Element, HTMLElement, Document, DocumentFragment, Text, Comment; attributes and
namespaces (`createElementNS`, SVG); tree mutation (`insertBefore`, `replaceChild`,
`cloneNode`, `before`/`after`/`replaceWith`); live `NodeList`/`HTMLCollection`;
`classList`, `dataset`, `style` (CSSStyleDeclaration); `innerHTML`/`outerHTML` (html5ever
fragment parsing; scripts inside are not run); element-scoped `querySelector(All)`,
`matches`, `closest`; events through deno_web's EventTarget with spec dispatch along the
DOM path; inline `on*` attributes; `MutationObserver`; `IntersectionObserver` and
`ResizeObserver` from the frame loop; `requestAnimationFrame` on the frame clock;
`history` (`pushState`/`replaceState`/`popstate`); form controls and input events
(Blitz already edits text via Parley); `getComputedStyle` from Stylo computed values;
layout queries (`getBoundingClientRect`, `offset*`, `client*`, `scroll*`) from Blitz;
ES modules via the deno_core module loader backed by our network; cookies via
`cookie_store`. Release node wrappers and listeners when nodes are removed (today's
`nodes`/`listeners` maps in `dom.js` leak).

Reuse with attribution: algorithms from **domino** (BSD-2-Clause, Mozilla's spec DOM
used by Angular SSR), **happy-dom** (MIT) and **linkedom** (ISC). Copy individual
algorithms, never their whole DOM.

Gate: every fixture in `tests/compat.rs` passes un-ignored; a WPT `dom/` subset runs in
CI with its pass rate recorded (it may only go up). Blitz's repository has a `wpt/`
runner to adapt.

### P4: speed and RAM

- **Startup snapshot** of all bindings and polyfills, embedded in the binary. The OS
  shares its pages across tab processes and startup is faster.
- Lite mode for background and simple pages, full JIT for active app pages;
  `low_memory_notification()` and dropping decoded images and caches on freeze.
- The worker reports **RSS** in `Event::State` (`src/engine_protocol.rs`, bump the
  protocol version), shown next to `js_heap`.
- **Shared network broker** in the browser process (one TLS stack, HTTP cache and cookie
  jar for all tabs) instead of a reqwest pool with 4 threads per worker.
- Stylo's rayon pool capped at 2 threads, used only above a DOM-size threshold; raster
  on its own thread from a display-list snapshot; frames through shared memory instead of
  full RGBA over the pipe; V8 platform thread pool capped at 2.
- Linux/Docker: `MALLOC_ARENA_MAX=2` for workers and `malloc_trim` on freeze.

Gate: `scripts/browser-bench.py` (see [reliability-baseline.md](reliability-baseline.md)) on the 10 reference pages in engine-strategy.md, with
per-tab RSS and load time against Servo, recorded here. Targets: article under 100 MB,
app page under 250 MB, frozen tab under 10 MB.

### P5: CSS completeness

Switch painting to the **Skia** backend (`anyrender_skia`; Skia BSD-3, skia-safe MIT):
full filters and `backdrop-filter`, and faster. Fix Blitz gaps that real sites hit
(per blitz.is/status/css): `overflow: auto` scroll containers, `position: sticky`,
`text-overflow`/`line-clamp`, `text-shadow`, `mix-blend-mode`, container queries;
later multicol, 3D transforms and `border-image`. Patch a vendored Blitz via
`[patch.crates-io]` (the `vendor/README.md` convention) and upstream every fix.

Gate: a WPT `css/` subset ratchet plus pixel snapshot tests of the reference pages.

### P6: rollout

Per-site engine preference, automatic reload in Servo when the missing-API tracker or a
fatal error says the page needs it, an engine badge in the address bar, and a default-on
allowlist. Video/audio DRM, WebGL/WebGPU and complex editors stay on Servo for now.

## 7. Testing rules

- Report green only from a **clean** target (`cargo clean` or a fresh `--target-dir`).
  Stale artifacts have hidden broken builds before.
- Every bug fix gets a regression test, proven by mutation.
- Commands:
  ```sh
  cargo test --locked --manifest-path engines/Cargo.toml --target-dir target/wega-engine
  cargo clippy --locked --manifest-path engines/Cargo.toml --target-dir target/wega-engine --all-targets -- -D warnings
  cargo fmt --manifest-path engines/Cargo.toml --check
  python3 scripts/build-wega-engine.py --debug && python3 scripts/native-tests.py --suite engine
  ```
- Coverage: `coverage-policy.json` requires line measurements for first-party engine
  code. `engines/vendor/**` is classified as third-party and `engines/v8-spike/**` as test-only.
